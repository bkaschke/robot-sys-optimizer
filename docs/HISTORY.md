## Kinematics API (M1)

- `core.robot.Robot.from_registry("ur20")` provides `fk(q)` → T_base_flange (4×4, in `base_link`), `frame_pose(q, link)`, `jacobian(q, offset_flange)` (6×n, rows lin/ang, base-aligned, at a point fixed to the flange), `manipulability`, `gravity_torques(q)`, and `static_torques(q, payload_kg, payload_com, wrench, wrench_point)`.
- Sign convention: `wrench` is what the tool exerts **on** the environment (base-aligned), so τ = g(q) + J_comᵀ(−m·g) + Jᵀ·wrench.
- Gravity defaults to −z in `base_link` (floor mount). Pass `gravity_base` for wall or ceiling mounts.
- `core.ik.make_ik(robot)` dispatches on `spec.ik`. Every solver has `solve(T) → (k, 6)`. Analytic results are wrapped to (−π, π] with one row per branch (≤ 8). `expand_to_limits()` adds the ±2π copies a joint range allows.
- `URAnalyticIK` measures the URDF↔DH frame offsets at construction; nothing UR-specific is hard-coded beyond the DH table in `spec.yaml`. `NumericIK` is multi-start DLS on Pinocchio and works for any chain.
- The URDF rounds π/2 to 9 digits, so it differs from exact DH by about 1e-10. Joint-space comparisons near singularities therefore need about 1e-4 rad tolerance, while pose comparisons hold to about 1e-9.

## Viewer (M2)

- **State flow:** widgets → `ui.session.Session` (SI units, source of truth) → scene. A project file maps to and from `Session` via `to_project()` / `apply_project()`. Loading goes into a fresh `Session` first, so a broken project leaves the current one untouched.
- **Scene tree:** `/cell/base` is a transform gizmo at the robot `base_link` pose. Under it, `/cell/base/urdf_root` holds the ViserUrdf link frames. `/cell/part` is the part gizmo, with `/cell/part/mesh` under it.
- **Viser fires `on_update` when code assigns `.value`.** CellTab guards its callbacks with `self._busy` during refreshes. `PoseWidgets` uses `_syncing` for the gizmo↔field sync. Never round widget values for display: the next edit reads the rounded value back into the pose.
- `RobotView.link_pose_in_parent()` composes the pose from the scene handles (what the browser gets). It relies on ViserUrdf's private `_joint_frames` and `_joint_map_values`; `tests/test_app.py` breaks if a Viser upgrade changes them.
- **Assets:** project paths are relative to the project folder (default `workspace/default/`, gitignored), with the repo as fallback (golden parts). Uploads go to `<project>/assets/robots/<name>/` and `<project>/assets/parts/`.
- **URDF upload:** a zip goes through `core.urdf_import`, which guards against zip-slip and archive bombs, resolves `package://` and `file://`, and rejects xacro-only zips. An uploaded robot uses numeric IK, has unknown payload limits, uses the root link as base and the deepest leaf as flange. Continuous joints are not supported yet.
- Mount presets (floor, wall, ceiling) keep the base yaw. Any other rotation switches the mount to `custom`.
- Visual smoke test with no GPU: run the app, then `msedge --headless=new --use-angle=swiftshader --enable-unsafe-swiftshader --virtual-time-budget=40000 --screenshot=out.png http://127.0.0.1:<port>/`.

## Tool Setup (M3)

- **EE geometry (core/tool.py):** `T_flange_head = T_flange_mount · Rz(roll) · Tz(L) · Rx(θ) · Ty(d)` and `T_flange_tcp = T_flange_head · T_head_tcp`. The extension collision is capsules of `radius`: segment 1 runs from the mount origin along mount z for L; segment 2 (only when d ≠ 0) is the lateral leg to the head origin. A `straight` extension forces θ = d = 0. The head frame is the EE URDF root link, and head links are rigid.
- `Extension` holds **ranges** (optimizer bounds) plus `nominal` (the user's rough placement, validated to lie inside the ranges). Changing a range in the GUI clamps the nominal value into it.
- **Contacts per TCP:** `contact_links` (whole links) and `contact_faces` (link → face indices on that link's *visual* mesh as loaded by yourdfpy). Collision filtering in M5 must use those same meshes and indices. Contact-free presets (scanning, spraying) clear all contacts.
- **Mass:** URDF inertials (head) + `kg_per_m` × extension length at segment midpoints. `mass_kg` and `com_head` override the head. `head_mass_known=False` when the URDF has no inertials and there is no override.
- **Tool library:** `tools/<name>.yaml` (EndEffector dump; name restricted to `[A-Za-z0-9_-]`). Saving an uploaded tool copies its URDF folder into `assets/tools/<name>/` so the entry is self-contained. The sample tools are stand-in geometry from `scripts/make_sample_tools.py`.
- **GUI edits** go through `ToolSetupTab._commit(fn)`: dump to a dict, apply the change, re-validate the whole `EndEffector`, and on error notify and revert the widgets. Meshes load only in `Session.set_tool`; parameter edits swap `tool_model.ee` without reloading.
- **Face picking:** a click ray (world) goes into the link frame, then `pick_face`, then `grow_region` (dihedral ≤ slider angle). Clicking an already-picked face removes its region. Picking is off until the checkbox is ticked.
- `CellTab.listeners` get `T_world_flange` after every base or joint change; the tool view follows the flange this way.

## Targets (M4)

- **The GUI has 6 tabs** (v2 order, shown numbered as steps): 1 Robot & cell (`Cell`), 2 External axis, 3 Tool (`Tool Setup`), 4 Targets, 5 Optimize, 6 Results. `app.TABS` keeps the internal names; `TAB_TITLES` the shown ones. Targets got its own tab instead of living in Tool Setup as the plan suggested.
- **Session state:** `session.targets` (schema.Targets) holds points in the **part frame** (m) with outward unit normals. Groups carry tolerances; a new group copies the current tool's process tolerances. The scene draws points, normals and the selection under `/cell/part`, so they follow the part gizmo.
- **Selection:** an array of face indices on `Session.part_mesh()` (scaled to m), cached per (path, units) and cleared when the mesh changes. Click selects a dihedral region; shift-click adds; ctrl/meta-click removes. You can also select by normal direction, or by box: `on_rect_select` projects face centres through `client.camera`, assuming an OpenCV camera frame. Box select ignores occlusion and has not been checked in a real browser yet.
- **Normals:** the default is barycentric interpolation of area-weighted vertex normals computed **from the selected faces only**, so normals never blend across the selection border. On the curved panel this gives < 0.05° interior error and ≤ ½ facet angle at the border. `normals="face"` gives flat normals.
- **Generators (`core/targets.py`):**
  - `projected_grid`: rays against the mean normal or a given direction; keeps only first hits on selected, front-facing faces.
  - `poisson_disk`: dart throwing on a hash grid; 0.7 s for 0.48 m² at 10 mm.
  - `raster`: `mesh_plane` sections, chained, resampled by arc length, serpentine. Note that `mesh_multiplane` returns **2D** coordinates, which caused a bug here.
  - `edge_paths`: the selection's boundary loops.
  - `parse_csv`: `x,y,z,nx,ny,nz[,group]`, optional header, mm or m.
- **Edits** apply to points lying on the selected surface: assign group, flip, delete. "Preview tool at point" draws a ghost of the tool posed with tcp.z = −n, at origin p + standoff·n (`targets_ui.target_tcp_pose`).

## Feasibility (M5)

- **Collision (`core/collision.py`):** a single Pinocchio `GeometryModel` holds the robot collision meshes (from the URDF), the tool extension capsules, the head link meshes split by contact signature, the part (BVH) and the floor (half-space at world z = 0). Pair categories and margins:
  - robot–part and tool–part: ≥ clearance.
  - tool–robot: ≥ 5 mm, with the last link (wrist_3) excluded.
  - robot self-pairs: |i − j| ≥ 2, minus any that touch at the neutral pose.
  - floor: links from upper_arm on, plus the tool.

  `collides(q, tcp)` uses Coal `security_margin`, so it is a clearance test, not just contact. A collision check takes about 0.7 ms.
- **Contact filtering is per TCP.** A link in `contact_links` is skipped whole. Picked `contact_faces` are skipped **plus their one-ring** (faces sharing a vertex), otherwise the rim faces at the contact edge always register as a collision.
- **Target frame / spin reference:** z = n; x = part +x projected onto the tangent plane (+y when n ∥ x). The TCP pose is `T0 · Rz(az) · Rx(tilt) · Rz(spin − az)` with `T0 = target · Rx(π)`, plus `standoff · n`.
- **Sampling:**
  - Spin: free = 30° steps; a range starts at its centre and works outward, ends included.
  - Tilt: 0, then rings at cone/2 and cone with 6 azimuths each.
  - Standoff: mid, lo, hi.

  Poses are tried with increasing tilt, and the **first pose with a feasible branch wins**; its best branch is chosen by manipulability + 0.1 × limit margin. Full cost-based choice comes in M7.
- **Checks, in order:** IK → joint limits − margin (the best 2π copy is kept) → static torque (τ = g + J_comᵀ(−mg) + Jᵀ F with F = −force·n; utilization ≤ limit; mass ≤ rated) → collision. An unreachable point reports the first stage nothing got past (`no_ik`, `joint_limits`, `torque`, `collision`). `marginal` means clearance < margin + 5 mm, torque > 90 % of its limit, or a joint within 15° of its limit.
- **Payload:** joint torque limits come from spec.yaml, with URDF effort as fallback. Payload-diagram and wrist-moment checks are reported as *skipped* until spec.yaml has them. `Robot.set_mount(R_world_base)` rotates gravity for wall and ceiling mounts.
- **GUI (Optimize tab):** the check runs in a thread on a **separate `Robot` instance**, because Pinocchio data is not thread-safe. Results go in `session.feasibility` (not saved, and stale after edits until re-run). Targets switch to "Color points by: feasibility". The inspector moves the robot to the chosen solution.
- **Speed:** reachable points take about 10 ms; unreachable points try every candidate (up to 13 tilts × 12 spins × 3 standoffs). The checker still uses the scalar IK; switch it to `solve_batch` when M7 needs throughput.

## Reachability (M6)

- **Batch IK:** `solve_batch(ik, T[N,4,4]) → q[N,8,6], valid[N,8]`, with branch index 4·i1 + 2·i5 + i3. Wrist-singular poses are marked invalid. `ur_manipulability` is the closed form |a2·a3·s3·s5·(a2·c2 + a3·c23 + d5·s234)| = |det J|, the same for any TCP offset and frame (verified against Pinocchio).
- **Map (`opt/reachability.py`):** IK + joint limits (with margin) only; no collision or torque. It relies on the **symmetry about base z**, which is valid when joint 1 turns a full revolution (every UR). It is stored on a 2D (r, z) grid × 600 Fibonacci tool-axis directions in the radial frame, taking any of 4 spins. `reach` is a boolean and `manip` the best |det J|. Defaults: 50 mm cells, about 70 s to build for UR20 + sander, then cached in `cache/reachability/<hash>.npz`. The hash covers the URDF bytes, DH, limits, `T_flange_tcp` and the settings, so **every tool length L gets its own map**. Non-UR robots raise `NotImplementedError`.
- **Lookup** is bilinear in (r, z). The tilt cone is applied **around the actual target axis** at query time; if the cone holds no direction, the nearest one is used. Dilating per direction bin instead (cone + half a bin) made the map optimistic and moved the optimum by 175 mm, and 200 directions were too few for a 10° cone.
- **Voting:** `vote_bases(map, P, N, cones, xs, ys, base_z, R_world_base, quality="min")`. Score = coverage + the worst target's normalized manipulability. **Base yaw has no effect**, by the symmetry. The "mean" quality is nearly flat, so its peak position is poorly defined; "min" (maximin) gives a sharp optimum. For the done-when the scene must not be mirror-symmetric, otherwise there are two equal optima.
- **GUI:** the "Base placement" panel in the Optimize tab draws the heatmap as an RGBA `add_image` on the floor and marks the best base. "Move base to best" goes through `CellTab.set_base`. **Viser image orientation:** columns run along +x, and **row 0 is at −y** (checked with a 2×2 test image), so the (ny, nx) vote grid is drawn unflipped.

## Station planner (M7)

- **Pipeline (`opt/placement.py`):**
  1. Candidate bases on a floor grid (100 mm) around the targets, minus the part's world-xy AABB grown by 0.25 m.
  2. Map coverage matrix (B × T), with "covered" meaning map score ≥ 0.5. Pruned to about 400 candidates: the best overall plus the 5 best per target.
  3. **CP-SAT** for each k from k_min to max_stations: maximize coverage ≫ Σ assigned manipulability ≫ fewer bases. The greedy cover is the fallback and sets k_min.
  4. Open-TSP order: brute force for k ≤ 7, otherwise nearest neighbour.
  5. **CMA-ES** per station (≤ 24 evaluations, σ 80 mm, within 0.3 m), scored by the exact checker on that station's targets with a 40-pose screening budget (`check_point(max_poses=...)`).
  6. `verify`: each target is checked exactly from its preferred station, then from every other one.
  7. Cost via `opt/cost.py` (the plan's J; μ normalized by the map max; c_ref 50 mm; D_ref 1 m; limits relative to 30°).

  Solutions are streamed through `on_solution` and returned sorted by cost.
- `FeasibilityChecker.set_base` / `CollisionScene.set_base` re-place the part and floor without rebuilding the geometry, which keeps refinement cheap (verified identical to a fresh build).
- **Results** are typed (`schema.Station`, `schema.Solution`; assignment = point id → station index) and saved in `project.results`. The per-point joint solutions (`session.result_points`, used for ghost robots) are kept only in memory.
- Travel is the straight-line distance between stations; obstacles are ignored in v1, so stations may sit on opposite sides of the part. Base yaw is kept from the current base.
- **GUI:** the Optimize tab has a "Station planner" panel (background thread, progress, cancel). The **Results** tab ranks solutions, shows a text cost-breakdown bar, colored station frames with labels, lines to the points each station serves, semi-transparent ghost UR20s (ViserUrdf with `mesh_color_override` RGBA) at each station's first solution, and "Move base to station".
- **Planning time** for the rail (21–25 points, k = 2..4) is about 15–30 s including refinement, with the map already cached.

## Tool geometry (M8)

- **Shared flange map:** for a *straight* tool (`T_flange_tcp` a pure +z translation, `is_straight`), `map_for_tool` returns `OffsetMap(flange map, offset)`, which looks up p − offset·a. This is exact because reachability then depends only on the flange pose and |det J| doesn't depend on the reference point. **One map (TCP = flange, about 50 s) serves every L.** Bent shapes fall back to a dedicated cached map per geometry, which is slow the first time.
- **Stage A (`opt/tool_geometry.py`):** coarse L scan (6 samples over the range) until the first L whose M7 plan reaches every target within `max_stations`, then bisection to `L_tol` (1 mm). It assumes coverage is monotone above L_min. The samples (`LSample`) form the coverage-vs-length table in the GUI. θ and d are pinned to the value in their range closest to 0 during stage A.
- **Stage B:** CMA-ES in normalized [0, 1] coordinates over whichever of θ, d and roll have non-degenerate ranges (θ and d only for `bent`). The stage A stations stay fixed, and each candidate is scored with `verify` plus the full cost J. The result is never worse than stage A.
- `_Evaluator` loads the head meshes once and swaps `tool_model.ee` per geometry; a `CollisionScene` is rebuilt per geometry because the capsule length changes.
- **GUI:** the Optimize tab's "Tool geometry" panel has max stations, L tolerance and the number of shape evaluations. It shows a coverage-vs-L table, adds its solution (with `tool_values`) to Results, and "Apply to tool" writes the values into the tool's nominal via `ToolSetupTab._commit`.
- **Speed:** the deep hole with 1 target takes about 6 s; the rail-sized scenes take about 15 s per L sample.

## Carriers (M9)

- **`schema.Base`:**
  - `mode` is static or movable; `carrier` is rail, gantry or mobile (positioner is rejected for now).
  - `pose` is the track or gantry frame in the world.
  - `chassis` is the moving body (mobile chassis or carriage) with its bottom on the carriage frame; `riser` sits on top of it; `track` is the static rail body, centred on the travel range.
  - `T_mount`; `joints` holds the travel ranges.
  - `keepouts` are world floor boxes.
  - `standoff_m` holds the minimum, preferred and keep-out clearance; `localization_m` and `localization_deg` apply to mobile; `tip_over` and `tip_margin_m` too.
  - The robot base pose is `T_world_carriage(dofs) · Tz(lift) · T_mount`.
  - The DOFs are: rail s; gantry x, y; mobile x, y, yaw (+ lift). A `Station` stores its `carrier` DOF values.
- **Static mode means exactly one base (k = 1)**, as in the plan: the planner places a single free-floor base. Several stations need movable mode with a carrier. The M7 GUI test now uses the default mobile base.
- **`core/carrier.py`** handles the DOFs and bounds, `T_world_base`, `values_for_base` (inverse, for the GUI), the bodies, and the footprint (union of convex hulls). Travel is |Δs| for a rail, max(|Δx|, |Δy|) for a gantry (axes move together), and a straight line for a mobile base (v1). It also builds a carrier URDF (checked: Pinocchio FK of `mount` = `T_world_base`) and runs the **tip-over** check: the centre of pressure of the chassis, riser, arm (Pinocchio COM), tool and the part's reaction to the process force must lie inside the chassis footprint shrunk by the margin.
- **Standoff is a 3D distance** (as in the plan): a carrier may sit partly *under* a raised part if it stays ≥ the minimum away in 3D. Real fixtures/stands must therefore be part of the part mesh or keep-outs (found in the M9 test rewrite: the floating golden rail let the mobile chassis tuck under it).
- **`core/standoff.py`:** the part footprint is the **convex hull** of the projected mesh (conservative). The 2D check runs first and only failures are confirmed with a Coal **3D** distance, which lets an overhead gantry pass. The tolerance is 1 µm, because mesh float noise sits at exactly the minimum.
- **`opt/sites.py`:** `FloorSites` (the old M7 behaviour, part AABB + margin) and `CarrierSites` (carrier + zones). Sites supply candidates, `T(v)`, `accept(v)` → (ok, preferred-standoff penalty), the travel metric, tip-over per point, and the **localization perturbations** (±m in x and y, ±deg yaw: 6 extra exact checks per point for a mobile base). The planner refines in DOF space (CMA-ES pads 1-D rails to 2-D). `cost` adds a `standoff` term (`Weights.standoff`).
- **Carrier bodies in collision:** `CollisionScene(base_bodies=..., world_bodies=...)`. The carriage and riser are rigid in the base frame; the track is world-fixed and re-placed in `set_base`. They are checked against the arm from upper_arm on and against the tool, with `self_clearance`.
- **Bug fixed in M7 code:** `min_stations` used the greedy count, which is an upper bound, so smaller station counts were never tried. It is now an exact CP-SAT minimum set cover.
- **Done-when scene, and why it is this one:** with a UR20, the rail's *top* face needs 2 stations for both carriers; the single-station spans are rail 3.35 m and mobile 3.15 m, so the reach hides the difference. On the **wall-side face** with a wall keep-out (the robot must reach over the part), the spans are rail 2.05 m and mobile 1.55 m. The exact plan gives rail 4 stations against mobile 5 (mobile with ±10 mm / ±1° localization). Both carriers carry the robot at a 0.7 m mount. On the near face the mobile base is better (3.4 m against 1.6 m), so "rail beats mobile" is not universal.
- **GUI:** (M9: Cell → "Base mode"; now the External Axis tab, see "Carrier builder") (fields → **Apply** validates as `schema.Base`; "Load carrier defaults" for rail, gantry or mobile). It has DOF sliders that jog the carrier (driving the robot base), draws the bodies, the standoff shells (red minimum, amber preferred) and the keep-outs, and shows a live footprint-to-part distance.
- **Viser gotcha:** setting `gizmo.visible = False` hides the gizmo's whole **subtree**; the robot hangs under the base gizmo and the part, targets and selection under the part gizmo. "Show gizmo" therefore toggles `disable_axes`, `disable_sliders` and `disable_rotations` (`PoseWidgets.set_handles`). This was broken since M2.
- **Headless screenshots occasionally capture before the scene streams in** (an empty view with "Connected"). Re-take them, and use a fresh port after killing a server, because Viser silently moves to the next free port.

## Exports (M10)

- **`core/export.py`:**
  - `station_pose(base, station, T0)` gives the exact base pose: carrier stations recompute it from the DOFs, which keeps inverted gantry mounts right; floor stations keep the planned orientation.
  - `tcp_rows` / `rows_to_csv`: one row per point in station order, unreached points last. Columns are documented in `CSV_COLUMNS`. TCP poses are in the world (mm + quaternion wxyz) and base (mm + rpy) frames, plus joints (deg), spin, tilt, standoff, clearance, manipulability, torque and limit margin. Each pose is recomputed from the stored joint solution.
  - `tool_urdf` / `export_tool`: the chain flange → mount → extension_k (cylinder + sphere caps, mass per m) → head links (copied from the head URDF) → `tcp_<name>`. The head mesh folders are copied next to the URDF.
  - `envelope_svg`: a dimensioned side view in the bend plane.
- **`core/report.py`:** `build_report(ReportInput)` builds a self-contained HTML page with inline CSS, inline SVG and data-URI PNGs. It has no `<script>` and no `<link>`, and the test checks that every `src`/`href` is a data URI.

## Joint-configuration zoning (post-v1)

- **Labels (`core/configs.py`):** `S±E±W±` = signs of the three factors of |det J|: horizontal reach a2·c2 + a3·c23 + d5·s234 (shoulder), sin q3 (elbow), sin q5 (wrist). They are distinct for all 8 analytic branches (tested on 200 random poses) and invariant to ±2π copies. Non-UR arms: `E±W±`.
- **Checker:** `check_point` / `check_point_configs` share the generator `_feasible` (candidate poses in preference order, branches best first). `check_point_configs` returns the first feasible solution per label in ONE pass and stops once all 8 are found (`max_poses` 40 by default: unreachable configurations would otherwise cost a full pose sweep each). `PointResult` gained `config`, `zone`, `seq` (also in `PointResultData`).
- **`opt/zoning.zone_solution`** runs after `verify` when `PlannerSettings.zoning`: per station, options per point → `min_zones` (exact: config subsets by size, ties by total quality) → `_robust` again for any changed solution (fall back to the verified one) → `order_path` (PCA serpentine) → `unwrap_path` (DP over 2π copies, wrist joints weighted 2×; jumps > 180° in joints 4/6 counted). Changes = Σ (zones − 1) + wrist jumps; `cost_breakdown(config_changes=...)` with `Weights.config` (default 1.0; GUI *Cost per config change*). `Solution.zones: list[Zone]` (`core/schema_work.Zone`). The tool optimizer's stage B (`cost_at_stations`) zones too when the planner setting is on.
- **Measured** on the M9 wall-side rail task: without zoning every station had 2 configurations (4 changes); with zoning 0 changes, same 4 stations, J 18.86 → 18.87; planning 14 s → 47 s.
- **GUI/exports:** Station planner *Joint configuration* dropdown (`ui.stations.ZONING`) + *Cost per config change* (both saved in panel settings; `ToolOptPanel.planner_options = StationsPanel.options`). Results: zone summary and zone path lines. Targets colour by `zone` / `configuration` of the selected solution (`TargetsTab.selected_results`, redrawn on Results selection). CSV gains `zone, seq, config` (rows station → zone → seq); the report gains a zones table.

## Carrier builder (post-v1, External Axis tab)

- **Schema:** `Base.bodies: list[Primitive]`. A Primitive is a `box` (size), `cylinder` (radius, height) or `mesh` (file + `units`), with `name`, `pose` (in its parent frame), `attach` (`carriage` = moves with the DOFs, `fixed` = carrier frame `Base.pose`) and `kg`. Box/cylinder frames sit at the bottom-face centre; a mesh keeps its file origin.
- **Legacy:** projects with `chassis`/`riser`/`track` still work. `core.carrier.body_list(base)` converts them (riser on the chassis top, track centred on the rail range, attach fixed) with unique, URDF-safe names; `migrate(base)` rewrites a Base into body form (the GUI does this on load). The converted geometry is identical (`test_legacy_fields_convert_to_same_geometry`), and the M9 regression counts are unchanged.
- **`Carrier(base, T_static, resolve=...)`:** `resolve` maps mesh paths (Session passes `Session.resolve`: project folder, then repo). Meshes load once per Carrier (`_load_mesh` is also lru-cached by path + mtime + units). Tip-over sums every carriage body's mass; the **support polygon** is the hull of the carriage bodies within 20 mm of the lowest carriage point (wheels, not the raised chassis). The standoff footprint stays the union of per-body hulls. The carrier URDF has one link per body (`body_<name>` on the carriage, `fixed_<name>` on the world; FK verified).
- **GUI (`ui/carrier_ui.py` + `ui/carrier_bodies.py`):** the panel keeps a working `bodies` list and `mount_pose`; body and mount edits call `commit()` at once, while the axis-type and safety fields wait for **Apply**. `commit()` also loads every mesh, so a missing or broken file fails there and not mid-plan. DOF sliders are rebuilt only when the DOFs or ranges change (`_dof_sig`); `load()` resets the signature so a loaded project's base pose wins over stale sliders. The body and mount gizmos live under `/carrier_edit/*` (not under the base gizmo) and are re-placed after every draw. Button actions are methods (`add_shape`, `snap_mount`, `add_mesh_bytes`) so tests drive the same code as the buttons.
- **Examples:** `scripts/make_examples.py` writes `examples/rail_long_part` and `examples/mobile_amr` (repo-relative asset paths). Project → *Examples* copies one to `workspace/examples/<name>/` before loading, so saving never edits the shipped copy. `tests/test_examples.py` loads both and plans them to full coverage.

## Target tools (post-v1)

- **`core/target_tools.py`:** `lattice_grid(mesh, faces, row, col, direction, row_dir, anchor)` puts points at anchor + i·col·u + j·row·v (u = projected `row_dir`, rows serpentine) and casts them along d onto the faces. Anchoring at the part origin makes brush dabs share one lattice. `brush_faces` takes the connected faces within the radius whose normals are within the max angle of the clicked face (no spill over edges); `brush_dab` = lattice inside the sphere. `dedupe(P_new, N_new, P_old, tol)` uses a KD-tree (tol = 0.4 × min spacing in the GUI). `refine_mesh(mesh, max_edge)` = `trimesh.remesh.subdivide_to_size` with the parent-face index, refusing above about 2 M faces.
- **GUI (`ui/target_tools_ui.py`, folder "Brush & single points" + "Refine part mesh"):** click modes `add single point`, `remove point` (nearest within the brush radius) and `brush points`, plus "Fill selection with rows/columns" and an undo stack of added id lists. **Tessellate** writes `<project>/assets/parts/<stem>_refined_<N>mm.stl` in metres, switches the part to it (units `m`), carries the selection over by matching face centroids through the parent index, and calls `cell.refresh_part` (wired in app.py) so the scene and collision use the refined mesh.
- **Viser limitation:** there are no freehand drag events on scene meshes, only clicks and rect-select, so the brush works one dab per click. Fill selection covers large areas.

## v8 review fixes (2026-11, CODE_REVIEW_v8.md)

- **Worker jobs (`ui/jobs.py`):** explicit pickling; a result or message that cannot be pickled becomes an error / `warn`, never a hang. A crashed worker reports the exit code and the likely cause. Cancel crosses the process as `core.feasibility.CancelledError`; any other job error is `WorkerError` with `.summary` (one line) and `.worker_traceback`. Status lines show the one-liner, the traceback goes to the log.
- **Check pool (`opt/parallel.py`):** a broken pool is evicted and the run continues with serial checks plus a warning; pool-initializer errors are surfaced; `parallel.on_warn` is the UI hook for the message.
- **Uploads (`core/safe_io.py`):** `replace_file` / `replace_dir` validate the new data first, then replace; a rejected upload keeps the old file; a replaced file gives a "replaced existing" notice. The part fingerprint includes the mesh content hash, so old plans show as out of date once after the upgrade.
- **Reachability lookups** are memory-budgeted: `LOOKUP_ROWS` rows per block, at most `PAIR_BUDGET` (base, target) pairs per call (`opt/reachability.py`).
- **Plan stations / Quick plan** keep the previous results until the first new plan arrives; a failed run restores them; a station run never drops tool-optimizer designs. Cancelled Pareto / robust steps keep their plain labels with "(cancelled before the ... step)". Compare keeps finished rows on cancel and uses the station planner's collision settings.
- **Open project.json** loads into a new folder (`workspace/<stem>_<time>`), never over the current project; autosave and Save are blocked while loading.
- **Jog:** if the collision scene cannot be built, steps are blocked unless "Allow collisions" is on, and the readout shows a warning.
- **Collision geometry:** the deviation of a simplified mesh is measured and cached; a warning appears above half the clearance; the report lists collision geometry per body.
- **Margins:** `optimizer.margins` in the project is the single source for clearance / joint margin (Optimize tab); all planners and checks read it, it is recorded in provenance, and changing it marks plans out of date.
- **Reports / CSV:** `core/report.py` always has a "Not checked" section (payload / torque / dynamics, transit between stops, kinematic-only motion, sampled spin / tilt, collision geometry). The CSV starts with `#` comment rows (readers skip them); unmeasured clearance is an empty cell; "Export anyway" carries an OUT OF DATE banner; the UR notice only when `RobotSpec.mesh_license == "ur"`; PDF errors say whether the browser was missing or failed.
- **Other:** Delete all points asks first and Undo restores them. Tool-optimizer costs include carrier travel and the standoff penalty (values differ from earlier versions). Numeric IK is deterministic. A CSV with a BOM keeps its first row. Contour mode supports multi-body carriages.

## Batch queue (branch `feature/v8-batch-render-exe`)

- **Manifest (`core/batch.py`, no viser):** `batch.json` = `BatchManifest(cell_project, jobs)`; `BatchJob` = part (relative to the batch folder, `mesh_sha1`), `units`, `pose`, `selection` (face ids) or `selection_rule="tool_surface"` (+ `min_confidence`, `confidence`), `gen: GenSettings`, `planner` (settings snapshot, `ui.batch_planner`), `status`, `error`, `summary`, `run_s`. Statuses: pending, running, done, failed, cancelled, partial, needs_review (`bt.NeedsReview`). `check_job` refuses a missing, changed (hash) or unreadable mesh with a one-line reason.
- **Manifest on disk is the truth.** The GUI reloads before every edit; the runner writes one job at a time with `bt.update_job(path, job, fallback=)` so a panel edit and a run do not overwrite each other. `reset_interrupted` / `pending_jobs`: a job left `running` is pending again (resume); `done` jobs are skipped.
- **Runner (`ui/batch_job.py`, no viser):** `run_job` = materialize (`ui/batch_materialize.materialize`: copy the cell, add the part, apply the rule, `generate_targets`, auto-confirm the setup steps) → `plan_job.station_job` → save project → `report_make.export_all` (csv, userframes, report.html, no PDF) into `<job>/export/`. Any error → `failed` + `error.txt`; `CancelledError` → `partial` / `cancelled`; `NeedsReview` → `needs_review`. `run_batch` runs **a fresh worker process per job** (private `ui.jobs.Runner`, killed after each job) unless `in_process`. CLI: `python -m ui.batch_job <dir> [--in-process]`. `summary.csv` / `summary.html` are rewritten from the manifest after the run (`bt.write_summary`).
- **Lock:** `BatchPanel` sets `StationsPanel.blocked_reason` while a batch runs; plan buttons then notify "Cannot plan now". The panel also refuses to start while the Station planner runs.
- **Reports without a browser:** `report_make.make_report(..., notes=[NO_VIEWS_BATCH])` when no pictures exist; the GUI's 3D views come from `report_views.capture`.
- **Review pictures + page:** `core/soft_render.render(mesh, highlight=, secondary=, view=iso|top|front|side, size=, up=)` is a numpy z-buffer rasteriser (PNG bytes, 2x supersampled, double-sided, Lambert; triangles bucketed by screen size, no per-triangle loop below 32 px; 20k / 82k / 1.3M faces about 0.2 / 0.3 / 1.1 s at 480x360). `ui.batch_materialize.job_pictures` writes `<job>/review_iso.png` / `review_top.png` (needs_review jobs get a folder with just those), records `summary["review"]` (or `review_note` when rendering failed; it never fails a job), and `run_job` passes the images to `export_all(images=)`. Detection warnings are in `BatchJob.warnings`; detected / secondary faces are private attributes (not saved). `core/batch_review.review_html` / `write_review` build ONE self-contained `review.html` (data-URI pictures, inline CSS / JS, no URLs); `bt.write_summary` and `run_job` rewrite it; `ui.batch_materialize.build_review` renders missing pictures first (panel **Open review page**, CLI `--review-only`).
- Not implemented from the plan: a tool-optimization step per job (per-job PDF: done in v9, see "Usability round"), a drawn target preview at queue time (only the target count is shown), drag reordering (Move up / down instead).

## Rendering (R1-R3)

- **Update in place, redraw only what changed** (`ui/targets_draw.py`): selection as chunks under one frame (an add sends only the new faces), point cloud and normals updated in place when the count is unchanged (`_put`), colours built in numpy. Playback updates are batched and throttled; the Cell readout is throttled.
- **GLB vertex colours** (`ui/colour_mesh.py`): Viser 1.1.1 `add_mesh_simple` has no per-vertex colour, so heatmap and station areas are one GLB (`COLOR_0` with a hand-written material, since trimesh writes none). Modes and plans are cached as hidden nodes (`NodeCache`, `part_heatmap.KEEP`): switching only toggles visibility.
- **Display LOD** (`ui/display_lod.py`): above `DISPLAY_FACES` (300k) the part is drawn as a quadric-decimated copy (`TARGET_FACES` 200k); planning, collision and picking use the full mesh (picking casts the click ray against it). `Session.part_display()` returns (shown, n_full); `MeshCache` keeps 2 meshes. **Overlay lift** (`overlay_lift`) offsets overlays by the display copy's measured deviation, so they do not sink into it.
- **View (`ui/view_controls.py`):** Lighting Studio / Flat / Off from Viser's own lights and the bundled HDRI preset (`viser/_assets/hdri`), Shadows (key light, off by default), Fit view and Top/Front/Side/Iso (`view_pose`, `cell_bounds`). Refit on project load or a different part (`part_key` ignores `_refined_*mm`). **No external assets:** nothing is fetched at run time (check with the offline guard).
- **Report views (`ui/report_views.py`):** `capture(server, client, session, plan, views)` hides grid, gizmos and selection, frames with `view_pose`, retries a blank PNG (empty-scene race), restores the camera; captioned image grid in the report (`report_make.make_report(images=)`).

## Tool surface (T0-T4)

- **Pipeline:** `core/tool_surface.segment` (smooth regions: dihedral feature angle on meshes; STEP CAD faces merged when tangent) → `tool_surface_features.region_features` (area, up-facing, ray visibility from a cone around +Z, smoothness, height, boundary kinds convex / concave-tangent) → `tool_surface_pick.detect_tool_surface` (seeds = up-facing visible regions; grow across tangent joints, creases, and concave / tangent joints into steep walls facing into the selection; never across convex breaks into steep regions = `secondary` candidates; best set score with a height/reach factor; confidence from margin, near-threshold area and open creases; sanding warnings for pad radius and steep areas). Returns `ToolSurfaceGuess` (faces, confidence, regions with reasons, secondary, warnings, summary).
- **Every threshold is in `DEFAULT_PARAMS`** (`tool_surface_pick.py`); `detect_tool_surface(**params)` overrides and rejects unknown keys. Tune there, never inline.
- **Steep-wall assumption (user can correct):** walls inside a female cavity (join the floor by concave / tangent transitions, face into the selection) are tool surface; flange returns and faceplate sides (convex break) are not, they are secondary candidates.
- **Eval:** `core/tool_surface_eval` (area-weighted IoU / precision / recall, `load_sample`: `<name>/mandrel.(stl|step)` + `tool_surface.(stl|step)`, baselines) and `scripts/tool_surface_eval.py` (`--synthetic`, a samples folder with `--scale`, `--detector module:function`). Synthetic data: `core/mandrels.py` generators, `mandrel_cases.py` (EASY: smooth single patch; HARD in `mandrels_hard.py`: creases, steep female walls, decoy flanges and plinths, 25-30 deg tilts, perforations, pins; `expect` = `min_iou` or `ambiguous`). **Validated on synthetic data only**; real samples later in the two-file format.
- **GUI (`ui/tool_surface_ui.py`):** Targets → Detect tool surface runs in a thread, shows a preview layer (not the selection), confidence (low under 0.7), warnings, secondary Add buttons, Replace / Add to selection / Discard. Up = world +Z in the part frame (`ui.batch_materialize.detect_for_pose`, shared with the batch). Batch: `selection_rule="tool_surface"` + `min_confidence` → `needs_review` (see Batch).
- **STEP parts (`core/step_import.py`):** OCP tessellation (chord min(0.5 mm, 0.1 % diagonal)), `StepMesh.face_ids` per triangle, units come from the file, npz cache keyed by hash; `mesh.metadata["cad_face_ids"]` feeds segmentation.
